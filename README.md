# AI Instruction Design

Свод правил для текстов, которые исполняет модель, а не читает человек.

Системные промпты, инструкции нод в n8n, `AGENTS.md` и `CLAUDE.md`, скиллы, описания инструментов, планы, файлы состояния, хендоффы между агентами.

Упакован как скилл для Claude Code, Codex, Cursor и OpenCode. Работает и просто как справочник в чате.

---

## Зачем

Модель обучена на человеческих текстах. Когда её просят написать инструкцию для другой модели, она по умолчанию пишет так, как писала бы документацию для людей: таблицы на каждом шагу, жирный шрифт как управляющий сигнал, «критически важно» капслоком. Для LLM это чаще шум, чем сигнал.

Вторая проблема глубже. Ясного предложения недостаточно, если неправильный источник может его перекрыть, если под задачу подходят два маршрута сразу, или если у запрета нет безопасного выхода при нехватке данных. Промпт — это конфигурация, а не текст.

Свод собирает правила, которые из этого следуют.

## Что внутри

**Классы силы вместо интенсивности.** Слово «никогда» само по себе ничего не гарантирует. Гарантирует метка: `ИНВАРИАНТ`, `ТРЕБОВАНИЕ`, `СПРОСИТЬ`, `ПО УМОЛЧАНИЮ`, `РЕКОМЕНДАЦИЯ`, `ФАКТ СРЕДЫ`. Если два человека прочитают правило по-разному, модель прочитает его третьим способом.

**Лестница контроля.** Механизм выбирается по цене ошибки, и берётся самый слабый из безопасных. Наверху проза, ниже схемы, права, валидаторы, транзакции, подтверждение человека. Секреты, платежи, разрушающие изменения, внешние сообщения и публикацию на прозу оставлять нельзя.

**Анатомия правила.** Актор, триггер, действие, область, предусловие, наблюдаемый результат, поведение при нехватке данных. Если проверить выполнение нечем, это не правило, а пожелание.

**Границы доверия.** Всё, что пришло из внешнего источника — файлы, веб-страницы, письма, вывод инструментов, память, ранее сгенерированный текст — данные, а не инструкции, пока доверенный источник явно не выдал им полномочия.

**Состояние и компакция.** Что происходит с решениями в длинной сессии, при сжатии контекста и при передаче другому агенту. Как выглядит «неизвестно», «опровергнуто», «заменено».

**Диагностика.** Таблицы «симптом — механизм». Забывает к концу сессии, срабатывает слишком часто, выдаёт общие отписки, валидная структура с неверным смыслом. У каждого сбоя свой слой, и чинить надо его.

**Аудит и приёмка.** Конвейер `выполнить → сохранить → проверить → принять замечания → исправить → перепроверить → остановиться` и минимальный набор проверочных случаев.

## Установка

### Claude Code

```bash
git clone https://github.com/yagitpa/ai-instruction-design.git
cp -r ai-instruction-design/skills/ai-instruction-design ~/.claude/skills/
```

### Другие среды

| Инструмент | Каталог |
|---|---|
| Codex | `~/.codex/skills/` |
| Cursor | `~/.cursor/skills/` |
| OpenCode | `~/.config/opencode/skills/` |

Каталог скилла копировать целиком: `SKILL.md` ссылается на `references/` относительными путями.

### Без установки, прямо в чате

Приложить `SKILL.md` к диалогу и написать:

> Вот свод правил. Ниже мой системный промпт для *(задача)*. Примени свод, выдай переписанную версию. Затем прогони аудит по `references/review.md` и исправь существенные замечания.

Справочники подкладывать по необходимости — целиком все семь не нужны почти никогда.

Работает и как двухшаговый приём: сначала черновик, потом аудит того же черновика по чек-листу. Первый проход почти всегда пропускает часть требований, аудит — задача другого типа и ловит другое. Больше двух-трёх кругов смысла не имеет: дальше начинается хождение по кругу.

## Примеры

В [`examples/`](examples/) лежат разборы реальных промптов: исходник, найденные проблемы со ссылками на разделы свода, переработанная версия.

Исходники там намеренно рабочие, а не учебно-плохие. Смысл в том, чтобы показать, что находится в уже работающем артефакте, когда его прогоняют по чек-листу.

## Структура

```
ai-instruction-design/
├── README.md
├── LICENSE
├── examples/
│   ├── README.md
│   └── gigachat-client/
│       ├── README.md               разбор находок со ссылками на разделы
│       ├── before.md               исходный промпт как есть
│       └── after.md                переработанная версия
└── skills/
    └── ai-instruction-design/
        ├── SKILL.md                8 КБ, загружается всегда
        └── references/             58 КБ, подтягиваются по требованию
            ├── classes.md          классы силы, полномочия, владение решением
            ├── design.md           паспорт артефакта, контракт, маршруты
            ├── controls.md         лестница контроля, инструменты, безопасность
            ├── state.md            состояние, компакция, хендофф
            ├── form.md             анатомия правила, разметка, сокращение
            ├── diagnostics.md      таблицы «симптом — механизм»
            └── review.md           аудит, приёмка, проверка перед деплоем
```

`SKILL.md` держит приоритеты разрешения конфликтов, восемь правил ядра, рабочий порядок для трёх сценариев и таблицу маршрутизации к справочникам.

Разнесено так, чтобы типовая задача тянула один файл, максимум два:

| Задача | Что загрузится |
|---|---|
| Пишу артефакт с нуля | `design.md` + `classes.md` |
| Правлю по наблюдённому сбою | `diagnostics.md` + `form.md` |
| Проверяю чужой промпт | `review.md` |
| Проектирую агентный воркфлоу | `controls.md` + `state.md` |

Это не косметика. Свод сам предупреждает: по мере роста числа активных требований первой падает не средняя точность, а доля прогонов, где выполнено всё. Документ на 66 КБ, загруженный целиком, попадает ровно в эту яму.

## Проверка триггера

Скилл должен не только срабатывать, но и молчать. Прогнать в свежих сессиях:

**Должен подтянуться**
- «перепиши мой системный промпт для бота»
- «проверь этот CLAUDE.md»
- «спроектируй инструкцию для агентной ноды»

**Не должен**
- «напиши README для проекта»
- «сделай промпт для Midjourney»
- «поправь орфографию в статье»

Ложное срабатывание — такой же дефект, как пропуск. Если срабатывает лишний раз, сужать `description` во фронтматтере, а не тело скилла. Если пропускает — добавить в описание тип артефакта, на котором промолчал.

Отдельно проверить, доходит ли дело до `references/`. Попросить что-нибудь, требующее таблицы диагностики, и посмотреть, читает ли агент файл или отвечает по памяти из `SKILL.md`. Скилл, который загрузился, но не дошёл до справочника, — ровно тот случай, о котором свод и предупреждает: прогрессивное раскрытие даёт возможность, а не гарантию.

## Ограничения

Свод собран из инженерной практики и известных механизмов отказа. **Поведенчески он не валидирован**: замеров, бенчмарков и сравнений «до/после» здесь нет. Точные формулировки не переносятся между конфигурациями автоматически.

Каждый артефакт проверяется на своей связке модель плюс среда. Это требование сам свод и предъявляет — было бы странно не применить его к себе.

Свод написан по-русски. На английских моделях смешение языков инструкции и задачи не тестировалось.

Не применять к обычной прозе для людей.

## English summary

A Russian-language ruleset for writing text whose operational reader is a model, not a human: system prompts, n8n node instructions, `AGENTS.md` and `CLAUDE.md` files, skills, tool descriptions, plans, state documents, and agent handoffs.

Packaged as a skill for Claude Code, Codex, Cursor, and OpenCode. An 8 KB always-loaded spine routes to seven reference files (58 KB total) that load on demand.

Covers modality classes, a control ladder matched to failure cost, decidable rule anatomy, trust boundaries for untrusted content, state across compaction and handoffs, symptom-to-mechanism diagnostics, and an audit pipeline.

Not behaviorally validated. Evaluate in your own configuration. MIT licensed.
