--- НАЧАЛО ДОКУМЕНТАЦИИ GIGACHAT ---

Авторизация двухэтапная. Сначала по authorization key получаем временный access token, он живёт 30 минут. Затем этим токеном ходим в API.

Получение access token:

```python
import uuid
import requests

url = "https://ngw.devices.sberbank.ru:9443/api/v2/oauth"
headers = {
    "Content-Type": "application/x-www-form-urlencoded",
    "Accept": "application/json",
    "RqUID": str(uuid.uuid4()),
    "Authorization": f"Basic {GIGACHAT_AUTH_KEY}",
}
data = {"scope": GIGACHAT_SCOPE}
response = requests.post(url, headers=headers, data=data, timeout=30, verify=False)
response.raise_for_status()
access_token = response.json()["access_token"]
```

RqUID — уникальный идентификатор каждого запроса, обязательное требование API.
GIGACHAT_SCOPE для физлиц равен GIGACHAT_API_PERS.

Запрос к модели — через библиотеку openai как универсальный клиент:

```python
from openai import OpenAI
import httpx

client = OpenAI(
    api_key=access_token,
    base_url="https://gigachat.devices.sberbank.ru/api/v1",
    http_client=httpx.Client(verify=False),
)

completion = client.chat.completions.create(
    model="GigaChat",
    messages=[...],
    temperature=0.3,
)
answer = completion.choices[0].message.content
```

--- КОНЕЦ ДОКУМЕНТАЦИИ ---

## Что реализовать

### 1. Проверка TLS — через конфигурацию, не через комментарий

`ТРЕБОВАНИЕ:` Значение `verify` читается из переменной окружения `GIGACHAT_VERIFY_SSL`. Значение по умолчанию — `True`. Отключение возможно только явной установкой переменной в `false`.

`ИНВАРИАНТ:` Если `APP_ENV=production` и при этом `GIGACHAT_VERIFY_SSL=false`, модуль падает при импорте с сообщением:
`Проверка TLS отключена в production. Установите сертификаты НУЦ Минцифры или включите GIGACHAT_VERIFY_SSL.`

`ТРЕБОВАНИЕ:` При отключённой проверке модуль пишет в лог предупреждение один раз при инициализации, а не при каждом запросе.

`ПОЧЕМУ:` Комментарий в коде ничего не принуждает и не доезжает до среды исполнения. Между локальной разработкой и выкаткой должен стоять механизм, а не память разработчика.

`ТРЕБОВАНИЕ:` Предупреждения urllib3 об отключённой проверке гасить через `urllib3.disable_warnings` — только когда проверка действительно отключена.

### 2. Кэш токена

`ТРЕБОВАНИЕ:` Токен и время его получения хранятся на уровне модуля. Токен считается протухшим через 25 минут после получения.

`ТРЕБОВАНИЕ:` Запрос за новым токеном выполняется только при отсутствии токена, при истечении срока, либо при принудительном обновлении после 401.

`ТРЕБОВАНИЕ:` Обновление токена защищено локом. Одновременные вызовы при протухшем токене выполняют ровно один сетевой запрос за токеном, остальные ждут его результата.

`ПОЧЕМУ:` Бот асинхронный, несколько сообщений могут прийти в один момент.

`ФАКТ СРЕДЫ:` Запас в 5 минут от заявленных 30 взят намеренно, чтобы токен не протухал между проверкой и отправкой запроса.

### 3. Функция ask

```
ask(messages: list[dict]) -> str
```

`ТРЕБОВАНИЕ:` `messages` — список словарей с ключами `role` и `content`. Возвращается текст ответа модели, пропущенный через `clean_markdown`.

`ПО УМОЛЧАНИЮ:` `temperature = 0.3`. Условие выхода: значение можно переопределить необязательным аргументом функции.

`ПОЧЕМУ:` Бот-справочник, а не генератор идей. Но параметр может понадобиться другим командам бота, поэтому жёстко не зашивать.

`ТРЕБОВАНИЕ:` Каждый исходящий запрос несёт собственный `RqUID`. Значение сохраняется, чтобы попасть в лог при ошибке.

### 4. Обработка ошибок

`ТРЕБОВАНИЕ:` При ответе 401 — ровно одна попытка принудительного обновления токена и ровно один повтор запроса. Если повтор тоже вернул 401, бросить исключение с текстом, указывающим на проблему с авторизацией.

`ТРЕБОВАНИЕ:` При ответе 429 повтор не выполняется. Бросить отдельный тип исключения, чтобы вызывающий код мог отличить перегрузку от отказа авторизации.

`ТРЕБОВАНИЕ:` Сетевые ошибки и таймауты — записать в лог и бросить исключение. Повторы на сетевых ошибках в этой версии не делаются.

`ТРЕБОВАНИЕ:` Каждая запись в лог перед пробросом исключения содержит: тип ошибки, HTTP-код при наличии, `RqUID` запроса, признак того, была ли попытка обновления токена.

`ИНВАРИАНТ:` Пустой `except` и `except: pass` запрещены. Любое перехваченное исключение либо пробрасывается, либо логируется и пробрасывается в обёртке.

### 5. clean_markdown

```
clean_markdown(text: str) -> str
```

`ТРЕБОВАНИЕ:` Порядок операций:

1. Если весь текст целиком обёрнут парными тройными обратными кавычками — снять обрамление вместе с указателем языка, если он есть.
2. Выделить блоки кода (тройные кавычки и одиночные обратные кавычки) и исключить их содержимое из дальнейшей обработки.
3. В оставшемся тексте удалить символы `*`, `#`, `_`, `` ` ``.
4. Собрать результат обратно, сохранив исходный порядок фрагментов.

`ИНВАРИАНТ:` Содержимое блоков кода не изменяется.

`ТРЕБОВАНИЕ:` Непарное обрамление тройными кавычками не снимается — текст обрабатывается как обычный.

`ПОЧЕМУ:` Безусловное удаление этих символов ломает ответы с кодом, именами вида `snake_case` и арифметикой. Бот отвечает в том числе на технические вопросы.

## Критерии приёмки

Работа считается завершённой, когда выполнено всё перечисленное и результаты показаны мне:

1. Два последовательных вызова `ask()` выполняют ровно один запрос за токеном. Подтвердить счётчиком или строкой лога.
2. Одновременные вызовы при протухшем токене выполняют один запрос за токеном. Подтвердить сценарием с параллельными задачами.
3. При подставном 401 происходит ровно одно обновление токена и один повтор. При втором 401 бросается исключение.
4. `clean_markdown` прогнан минимум на трёх образцах: чистая проза со звёздочками; ответ с блоком кода внутри; ответ, целиком обёрнутый в тройные кавычки. Для каждого показать вход и выход.
5. При `APP_ENV=production` и `GIGACHAT_VERIFY_SSL=false` импорт модуля падает.

`ТРЕБОВАНИЕ:` Проверки прогнать реально и показать вывод. Утверждение о том, что проверки пройдены, результатом проверки не является.

## Контекст

Артефакт: обработчик текстовых сообщений в `main.py`.
Предусловие: `gigachat_client.ask()` принят и проверен.
`gigachat_client.py` в этом шаге не меняется. Если выяснится, что в нём нужна правка — сообщи, не правь молча.

## Что реализовать

`ТРЕБОВАНИЕ:` Обработчик текстовых сообщений вместо эха собирает список сообщений в порядке: системный промпт, история диалога, новый вопрос пользователя. Вызывает `ask()`, отправляет результат пользователю.

`ТРЕБОВАНИЕ:` Перед вызовом `ask()` в чат отправляется действие «печатает».

### Системный промпт

`ТРЕБОВАНИЕ:` Системный промпт хранится в отдельной константе модуля или в отдельном файле, не встроен в тело обработчика.

`СПРОСИТЬ:` Если содержимого системного промпта у тебя нет — запроси его у меня. Не сочиняй.

### История диалога

Это состояние, и оно описывается явно.

`ТРЕБОВАНИЕ:` История хранится в памяти процесса, отдельно для каждого чата.

`ТРЕБОВАНИЕ:` Хранится не более 10 последних пар «вопрос — ответ». При превышении отбрасываются самые старые пары целиком, парами, а не отдельными сообщениями.

`ИНВАРИАНТ:` Системный промпт в лимит не входит и не отбрасывается никогда.

`ТРЕБОВАНИЕ:` При перезапуске процесса история теряется. Это принятое решение, обходить его не нужно.

`ТРЕБОВАНИЕ:` В историю попадают только успешные обмены. Если `ask()` бросил исключение, вопрос пользователя в историю не записывается.

`ПОЧЕМУ:` Иначе после сбоя в контексте накопятся вопросы без ответов, и модель начнёт на них реагировать.

### Ошибки

`ТРЕБОВАНИЕ:` При любом исключении из `ask()` пользователю уходит:
`Сервис временно недоступен, попробуй ещё раз`

`ТРЕБОВАНИЕ:` Если исключение относится к типу «превышен лимит запросов» (429), пользователю уходит:
`Слишком много запросов, подожди немного`

`ТРЕБОВАНИЕ:` Полные детали исключения — в лог. Пользователю технические подробности не показываются.

## Критерии приёмки

1. Показать, что при 11-м обмене в одном чате в запрос уходит системный промпт и 10 последних пар.
2. Показать, что после исключения в `ask()` история чата не выросла.
3. Показать, что 429 и остальные ошибки дают разные сообщения пользователю.
4. Показать, что истории двух разных чатов не смешиваются.

## Условие остановки

Остановись после выполнения критериев приёмки. Не добавляй функциональность, о которой не просили: команды, кнопки, персистентность истории, стриминг ответа.
